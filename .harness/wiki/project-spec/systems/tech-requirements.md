# 기술 스택 요구사항

## 렌더링
- 2D 타일맵 (최소 256×256, 이상적 512×512 타일)
- 수백 개 폰 동시 렌더링
- 실시간 + 일시정지 + 4배속
- 타일별 오버레이 (온도, 구역, 아름다움 히트맵)

## 연산
- 폰 AI: 틱마다 다수 에이전트 상태 평가
- 경로 탐색: A* 또는 플로우 필드 (다수 에이전트 동시)
- 물리 없음: 충돌은 타일 기반 단순 처리
- 플러드 필: 방 인식, 구역 감지 빈번 수행

## 데이터 구조
- 게임 상태 전체 직렬화/역직렬화 (세이브/로드)
- 모든 게임 오브젝트 데이터 외부화 (XML/JSON Def)
- 폰당 수십 개 스탯, 수십 개 사고 동시 트래킹
- 수천 개 규모로 확장 가능해야 함

## 플랫폼
- PC 우선 (Windows / Mac / Linux)
- 모바일 미지원
- 멀티플레이 미지원

## 개발 제약
- 소규모 팀 (1~3인)
- 모딩 지원 가능한 구조 권장
- 장기 유지보수 가능한 아키텍처

## 에이전트 토론 필요 항목
1. 게임 엔진: Unity / Godot / Unreal / 커스텀
2. 언어: C# / C++ / Rust / Python
3. AI 아키텍처: BT / FSM / GOAP / HTN
4. 경로 탐색: A* 직접 구현 vs 라이브러리
5. 데이터: Def 시스템 구현 방식
6. 세이브: 직렬화 전략
7. 모딩: 외부 에셋/데이터 로딩
